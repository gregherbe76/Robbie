Build the Real-World Ingestion Layer for the Recruiting Intelligence Framework.

IMPORTANT:
The framework already has:
- candidate intelligence
- cross-agent cognition
- organization intelligence
- evaluation/calibration
- intelligence operations
- deterministic benchmark infrastructure
- OSS publication readiness

Now connect the framework to real-world signals.

This phase is NOT about:
- ATS workflows
- CRM functionality
- automation spam
- generic sourcing

This phase is about:
- trustworthy intelligence ingestion,
- provenance-preserving evidence acquisition,
- real signal normalization,
- live organizational cognition inputs.

--------------------------------------------------
Core Thesis
--------------------------------------------------

The quality of recruiting intelligence depends on:
- evidence quality,
- provenance quality,
- signal normalization,
- source reliability,
- explicit uncertainty.

The ingestion layer must:
- preserve provenance,
- preserve uncertainty,
- preserve source attribution,
- avoid hidden inference,
- avoid hallucinated enrichment.

--------------------------------------------------
1. IngestionGateway
--------------------------------------------------

Build the main ingestion orchestration layer.

Supported ingestion types:
- resume
- github
- linkedin
- interview_transcript
- portfolio
- organization_context
- references
- notes
- external_evidence

The gateway must:
- orchestrate adapters
- normalize evidence
- attach provenance
- preserve uncertainty
- deduplicate evidence
- avoid silent overwrites

Every ingestion operation must create:
- deterministic ingestion event
- provenance chain
- ingestion audit log

--------------------------------------------------

--------------------------------------------------

Build the candidate ingestion pipeline.

Pipeline stages:
- raw ingestion
- parsing
- normalization
- evidence extraction
- provenance attachment
- contradiction pre-check
- evidence graph insertion

Inputs:
- PDF resume
- markdown
- plain text
- GitHub profile
- LinkedIn export
- interview transcript

Output:
{
  normalizedCandidate,
  extractedEvidence,
  sourceReliability,
  ingestionWarnings,
  provenance
}

4. GitHubEvidenceAdapter
--------------------------------------------------

Build a real GitHub ingestion adapter.

Supported:
- repositories
- contribution activity
- commit density
- language distribution
- README evidence
- OSS participation
- collaboration graph

Extract evidence:
- ownership signals
- project complexity
- consistency
- maintenance patterns
- architecture indicators

IMPORTANT:

- follower count,
- vanity metrics.

- source URLs
- commit provenance
- extraction timestamps

Extract:

IMPORTANT:

--------------------------------------------------
6. ResumeParsingAdapter
--------------------------------------------------

Build deterministic resume parsing.

Requirements:
- section extraction
- chronology extraction
- skill extraction
- education extraction
- experience normalization
- ambiguity detection

Detect:
- vague descriptions
- unsupported scope claims
- timeline gaps
- duplicated phrasing
- keyword stuffing patterns

IMPORTANT:
Do NOT hallucinate structure.
Unknown sections remain unknown.

--------------------------------------------------

Build interview transcript ingestion.

Supported:
- plain transcript
- diarized transcript
- structured QA transcript

Extract:
- reasoning depth evidence
- contradiction evidence
- uncertainty indicators
- communication style
- ownership indicators
- technical depth signals

Preserve:
- speaker attribution
- timestamps
- quote provenance
- evidence references

--------------------------------------------------
8. EvidenceNormalizationEngine
--------------------------------------------------

Normalize all evidence into unified structures.

Evidence types:
- explicit_claim
- demonstrated_behavior
- contradiction_signal
- uncertainty_signal
- ownership_signal
- trajectory_signal
- organizational_signal

Every normalized evidence item must contain:
- source
- timestamp
- confidence
- reliability
- extractedBy
- derivedFrom
- rawReference

--------------------------------------------------
9. SourceReliabilityEngine
--------------------------------------------------

Estimate source reliability.

Examples:
- direct GitHub evidence → high reliability
- self-description → medium
- unsupported claim → low
- contradictory evidence → degraded reliability

Output:
{
  reliabilityScore,
  reliabilityFactors,
  uncertainty,
  conflicts
}

IMPORTANT:
Reliability must remain explainable.

--------------------------------------------------
10. ProvenanceCaptureEngine
--------------------------------------------------

Attach provenance everywhere.

Every evidence item must contain:
- producedBy
- producedAt
- ingestionSource
- extractionMethod
- derivedFrom
- rawReference
- confidence

No evidence without provenance.

--------------------------------------------------
11. EvidenceConflictDetector
--------------------------------------------------

Detect ingestion conflicts.

Examples:
- LinkedIn says "Staff Engineer"
- GitHub evidence suggests junior-level contributions

Or:
- timeline inconsistencies
- overlapping employment
- unsupported scope inflation

Output:
{
  conflicts,
  severity,
  impactedEvidence,
  unresolvedQuestions,
  recommendedInvestigation
}

--------------------------------------------------
12. IngestionAuditEngine
--------------------------------------------------

Track:
- ingestion events
- evidence transformations
- normalization steps
- provenance lineage
- source reliability changes
- conflict detections

Generate:
- replayable ingestion logs
- ingestion provenance graphs
- evidence lineage traces
